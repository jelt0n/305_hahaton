

## Запуск (Python 3.11+)

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-lock.txt
Copy-Item .env.example .env
```

В `.env` укажите `EE_PROJECT` — идентификатор своего Google Cloud проекта, зарегистрированного для Earth Engine, с включённым Earth Engine API и правами вашего аккаунта на использование проекта.

```powershell
.\.venv\Scripts\earthengine authenticate
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Без авторизации EE карта и поля работают; расчёт возвращает инструкцию настройки, а не искусственные данные. Для сервера можно указать `EE_SERVICE_ACCOUNT_FILE` — путь к JSON-ключу сервисного аккаунта с доступом к проекту. Не помещайте ключи в репозиторий или `static/`. После изменения `.env` перезапустите сервер.

В текущей рабочей папке также подготовлен локальный Python в `.runtime/python`. С ним сервис запускается командой `.\start.ps1`, а авторизация — `.\.runtime\python\Scripts\earthengine.exe authenticate`. Папка `.runtime` исключена из Git; для переноса проекта используйте стандартную установку выше.

## Работа с картой

1. Переместите карту к нужной территории. Начальная точка — сельскохозяйственная местность к западу от Краснодара. Кнопка ◎ запрашивает местоположение у браузера. Кнопка «Нарисовать участок» позволяет задать собственный контур: отметьте вершины и завершите контур.
2. Нажмите «Найти поля в этой области». Если область слишком велика, приблизьте карту. Загружаются только объекты `landuse=farmland`; размеченные иначе и отсутствующие в OSM поля не отображаются.
3. Выберите контур, период до одного года и порог облачности сцены.
4. Нажмите «Рассчитать NDVI». Появятся слой в границах поля, среднее / минимум / максимум, покрытие и даты снимков. Слой можно скрыть и изменить его непрозрачность.
5. «Скачать результат» сохраняет геометрию и статистику в GeoJSON (не растровый GeoTIFF).
6. «Восстановить ряд и найти аномалии» получает временной ряд за период до 120 дней. Выберите все спутники или только Sentinel-2. Историческая норма строится по сезонным окнам трёх предыдущих лет. Выбор спутников относится к временному ряду, растровый слой остаётся Sentinel-2.
7. На графике точки обозначают наблюдения, жёлтый пунктир — ряд с восстановлением, серая линия и полоса — норму ± стандартное отклонение. Переключатели включают серии, ползунок даты и нажатие на точку показывают подробности. CSV содержит наблюдения, восстановления, источник, норму, z-score, статус и погоду.
8. После получения ряда в боковой панели появляется слайдер «NDVI участка по дням». Он синхронизирован с датой графика и окрашивает весь выбранный контур по среднему NDVI дня на шкале −1…+1. Это единый цвет среднего по полю, не попиксельный снимок за дату. Восстановленные значения явно подписаны и имеют пунктирный контур; отсутствие данных показано серым. Стрелки переключают соседние дни. Управление остаётся доступно после закрытия графика. Во время дневной окраски медианный растровый слой скрыт; отключение дневной окраски возвращает ранее видимый композит. Смена поля или периода сбрасывает дневной слой.


## Обучение и воспроизводимость

```powershell
.\.runtime\python\python.exe -m gapfill train --input "Ваш_путь" --output models/ndvi --seed 42 --iterations 650
```

Укажите путь к своему train. Команда делит поля на обучение / настройку / holdout, создаёт случайные 20% и 30-дневные блочные пропуски, сравнивает пять простых методов и CatBoost, выбирает конфигурацию на tuning и проверяет на holdout. Затем переобучает модель на всех полях. Выход: `model.cbm`, `config.json`, `metrics.json`. Для нового эксперимента задайте другую папку `--output`, иначе файлы модели перезаписываются.

Скрытые цели и динамические признаки маскируются до вычисления соседей. Готовые `status`, `ndvi_zscore`, климатология и `n_reference_years` не используются. Модель предсказывает поправку к линейной интерполяции; выбранный вес CatBoost — 1. Метрики относятся к модели до финального переобучения, не к закрытому тесту. В `metrics.json` сохранены параметры, seed, ID разбиений, SHA-256 train и ошибки по сегментам.

Проверенное окружение — Python 3.12.10, CatBoost 1.2.10. `requirements-lock.txt` фиксирует установленные версии, включая библиотеки анализа файлов; `requirements.txt` содержит диапазоны основных зависимостей. Модель находится в `models/ndvi`, исходный train в репозиторий не копировался.

## Методика временного ряда и аномалий

Веб-ряд использует S2 SR Harmonized (10 м, SCL), Landsat 8/9 Collection 2 Level 2 (30 м, QA, коэффициент 0.0000275 и смещение -0.2), MOD13Q1 (250 м, SummaryQA=0, масштаб 0.0001), ERA5-Land DAILY_AGGR (температура °C, осадки мм). Несколько гранул одного сенсора на дату усредняются. Primary NDVI выбирается по приоритету S2 → Landsat → MODIS, как в train. Это не межсенсорная калибровка. MODIS — 16-дневный композит с датой начала периода, а не мгновенное наблюдение.

К выбранному периоду добавляются края по 20 дней и соответствующие окна трёх предыдущих лет. Модель использует наблюдения до и после пропуска (ретроспективное восстановление). Наблюдения сохраняются. Для веб-дня дальше 30 дней от ближайшего наблюдения текущего года восстановление не показывается. В пакетном режиме полностью пустой контекст получает сезонный либо фиксированный fallback 0.35 для конечного ответа; это низкоинформативный случай.

Норма дня — среднее NDVI прошлых лет в окне ±15 дней дня года. Нужны минимум 5 наблюдений и 2 года. `z = (NDVI - mean) / max(std, 0.05)`. При z ≥ -1 развитие штатное; -2 ≤ z < -1 — угнетение; z < -2 — критическая аномалия. В список периодов входят минимум три подряд идущих дня с z < -1. Восстановленные дни тоже участвуют; период без наблюдаемых точек явно помечается.

Температура участвует в детекции независимо от NDVI. Загружается ERA5-Land за те же сезонные окна прошлых лет. Норма температуры требует минимум 10 наблюдений и 2 разных года в окне ±15 дней. `z_temperature = (temperature - temperature_mean) / max(temperature_std, 2 °C)`. При z ≥ 2 отмечается необычно высокая температура, при z ≤ -2 — необычно низкая. В список входят минимум 3 подряд идущих календарных дня одного типа; отсутствие температуры или нормы прерывает период. Это отклонение относительно сезона, а не универсальный порог повреждения культуры.

Температурные эпизоды показываются даже без снижения NDVI и при отсутствии спутниковых наблюдений, если доступна погода. Совпадение температурного и NDVI-сигналов отмечается отдельно с количеством совпавших дней; оно не доказывает причинность. Осадки пока дополняют описание: при полном покрытии периода длиной ≥7 дней и сумме <2 мм отмечается возможный дефицит влаги. Температурный график, норма, z-score, статусы и совпадения доступны в интерфейсе и CSV. Референс за три года — короткий исторический ориентир, не 30-летняя климатическая норма.

Обучение — апрель–октябрь 2010–2024; зимние даты и новые регионы требуют отдельной оценки. Культура OSM-поля неизвестна, EVI/NDWI в веб-потоке пока не загружаются: для модели эти признаки отсутствуют. MODIS и ERA5 имеют грубую сетку, возможны смешанные пиксели. Частичные ошибки источников выводятся как предупреждения, полное отсутствие снимков не заменяется выдуманными наблюдениями.

## Методика

Источник: `COPERNICUS/S2_SR_HARMONIZED`. NDVI вычисляется для каждого снимка как `(B8-B4)/(B8+B4)`, затем строится попиксельная медиана за период. Конечная дата включается. Исключаются SCL 0, 1, 3, 7, 8, 9, 10, 11 (нет данных, дефекты, тени, неопределённые пиксели, облака, снег). Маска SCL имеет разрешение 20 м; диапазоны NDVI — 10 м. Порог облачности относится к целой сцене, а не к выбранному участку.

Статистика рассчитывается по композиту на сетке 10 м в проекции первого снимка; покрытие показывает площадь доступных пикселей относительно площади контура. При неполном покрытии статистика характеризует только наблюдаемую часть поля. Маска облаков не идеальна. NDVI не является прямой оценкой урожайности. Число сцен — число гранул, а даты съёмки дополнительно объединены по дням.

Поддерживаются замкнутые OSM ways, multipolygon relations с раздельными внешними контурами, составными кольцами и внутренними вырезами. Невалидные и незамкнутые контуры пропускаются. Максимум участка — 10 000 га и 20 000 вершин. Область поиска ограничена 0,15° × 0,25°, кэш OSM — 5 минут, не более двух одновременных расчётов EE на процесс.

## Проверки и API

```powershell
.\.venv\Scripts\python -m pytest -q
```

API-документация: `/docs`. `GET /api/fields?bbox=south,west,north,east`, `GET /api/health`, `POST /api/ndvi` с JSON `{geometry, start, end, cloud}`. Тесты проверяют геометрию OSM, валидацию, включение конечной даты и ошибки внешних сервисов; вычисления EE в тестах подменены. Полная проверка реальных спутниковых значений требует авторизованного EE-проекта.

Также `POST /api/timeseries` принимает `{geometry, start, end, cloud, source: "all" | "s2", history_years: 3}`. Выполнено 28 тестов, включая отсутствие утечки скрытых целей, submission, жару при нормальном NDVI, холод одновременно с угнетением, пропуски температуры и отсутствие спутниковых данных. Живая проверка GEE дала 10 наблюдений и 20 восстановленных дней за 01–30.07.2026; все четыре источника доступны. Синтаксис JavaScript проверен. Визуальная проверка браузером недоступна в рабочей сессии.

Сервис предназначен для локального запуска. Перед публичным размещением нужны авторизация пользователей, ограничения запросов и квот на уровне сервера / reverse proxy. API принимает произвольный валидный полигон в пределах лимита; UI отправляет выбранный OSM-контур. Используются внешние OSM-тайлы, Overpass, Google Fonts и Leaflet CDN; необходим интернет. Ссылки на тайлы EE временные: повторный расчёт обновляет их.
